\noindent\textbf{Note on this revision.} ClinTox is dropped from this benchmark (see main text Introduction); its supplementary ablation table (formerly Table~S4) is removed. Four TDC ADMET Group datasets are added -- hERG, DILI (binary classification) and Caco-2, Half-Life (regression) -- each with a full ablation table (Tables~S5-S8). Table~S2 (BBBP)'s E2E LoRA block has been corrected against current on-disk training logs (see note at Table~S2); all other retained tables (S1, S3, S4) are unchanged from Revision 1. Section~S5 is substantially rewritten: Chemprop and GCN are now also benchmarked in-house on the identical scaffold split and protocol as every CLM-based method, across all seven datasets, addressing the reviewer comment that GNN baselines were previously only cited from external papers.

\subsection*{Table S1: 473-Dimensional Physicochemical Feature Vector}
%% -----------------------------------------------------------------------------

The physicochemical (PC) feature vector concatenates four descriptor groups computed
with RDKit~3.x and NetworkX~3.x. This vector, and the PC-only baseline built from it,
is identical across all seven datasets in this revision, including the four TDC
ADMET tasks.
Morgan fingerprints are computed at radius 2 with 128 bits using
\texttt{GetMorganGenerator}; MACCS keys use the standard 167-bit MACCS key
definition (\texttt{MACCSkeys.GenMACCSKeys}).
RDKit descriptors are drawn from \texttt{Descriptors.descList} after removing
68 features found to be numerically unstable, redundant, or near-zero variance
on drug-like molecules (BCUT descriptors, partial-charge extrema, $\chi$-series,
Kappa indices, etc.).

\phantomsection\addcontentsline{toc}{subsection}{Section S1: Zero-Shot vs.\ Full Finetuning}
\subsection*{Section S1: Zero-Shot vs.\ Full Finetuning}
%% -----------------------------------------------------------------------------

\paragraph{Zero-shot evaluation.}
Zero-shot performance of CLMs on molecular property prediction tasks is generally
poor for binary/multi-class classification because the models were pretrained to reconstruct SMILES tokens (masked-language modelling) or predict molecular properties via regression (multi-task regression), not to output class labels. Without finetuning, CLM representations encode general molecular structure but lack task-specific discriminative features.
Empirically, zero-shot linear probes on BACE achieve MCC~$< 0.1$ for
ChemBERTa models not specifically pre-trained on binding-affinity data, confirming that task alignment is essential.

\paragraph{Full finetuning vs.\ LoRA.}
Full finetuning updates all model parameters for the downstream task, maximizing task-specific adaptation but incurring high memory cost ($\mathcal{O}(|\theta|)$ gradient storage) and risking catastrophic forgetting of pre-trained chemical knowledge.

Low-Rank Adaptation (LoRA) decomposes the weight update $\Delta W \in \mathbb{R}^{d \times k}$
as the product $BA$ where $B \in \mathbb{R}^{d \times r}$, $A \in \mathbb{R}^{r \times k}$
with $r \ll \min(d, k)$, reducing trainable parameters by $76-97\%$ without degrading
predictive accuracy.
Across all seven PEARL datasets, LoRA-finetuned models match or exceed full finetuning
benchmarks reported in prior work (MolFormer BBBP MCC~$= 0.767$; Uni-Mol WL BACE
MCC~$= 0.623$), confirming that the task-relevant weight update lives in a low-rank
subspace, including for the four regression/binary TDC ADMET tasks.

\paragraph{Comparison to reported baselines.}
MolFormer-XL full finetuning on BBBP achieves MCC~$\approx 0.79$ in the original paper~\cite{ross2022molformer}; our LoRA result (MCC~$= 0.767$) is close using
only $6-9\%$ of parameters.
No directly comparable published LoRA baseline exists for the TDC ADMET Group datasets
(hERG, DILI, Caco-2, Half-Life), so Section~S5 below reports the in-house
PC-only/Chemprop/GCN comparison instead.

%% -----------------------------------------------------------------------------
\phantomsection\addcontentsline{toc}{subsection}{Section S2: LoRA for Uni-Mol - Mathematical Formulation and Implementation Details}
\subsection*{Section S2: LoRA for Uni-Mol - Mathematical Formulation and
Implementation Details}
%% -----------------------------------------------------------------------------

\paragraph{Architecture background.}
Uni-Mol~\cite{zhou2023unimol} is a SE(3)-equivariant Transformer operating on
3D atomic coordinate inputs.
Each attention layer computes
$\text{Attn}(Q, K, V) = \text{softmax}\!\left(\tfrac{QK^\top}{\sqrt{d_k}}\right)V$
where the projection matrices $W_Q, W_K, W_V, W_O \in \mathbb{R}^{d \times d}$
are merged into a single \texttt{in\_proj} weight matrix of shape
$\mathbb{R}^{3d \times d}$ in the PyTorch implementation
(where $d = 512$ for the base Uni-Mol model).

\paragraph{LoRA targeting.}
For Uni-Mol, LoRA adapters are applied exclusively to the \texttt{in\_proj} weight
matrices of all self-attention layers.
Each adapter decomposes $\Delta W_{\texttt{in\_proj}} \approx B\,A$ with
$B \in \mathbb{R}^{3d \times r}$, $A \in \mathbb{R}^{r \times d}$, scaling by
$\alpha / r$ at inference.
This targeting is preferred over query-only or query+value targeting because
the merged \texttt{in\_proj} encodes $Q$, $K$, and $V$ projections jointly;
adapting only part of it creates gradient flow asymmetries that degrade convergence.

\paragraph{Gradient flow preservation.}
SE(3)-equivariant message passing in Uni-Mol depends on pair distances computed
from explicit 3D coordinates.
To preserve equivariance, only the attention projection weights are adapted;
distance-based pair encodings ($\boldsymbol{\phi}(\|r_i - r_j\|)$) are kept frozen.
The gradient from the downstream loss (classification or Huber regression) flows
through the LoRA adapter and into the conformer features,
providing indirect adaptation of the 3D representation regardless of task type.

\paragraph{Conformer caching.}
Uni-Mol requires 3D conformers generated by ETKDGv3~+ MMFF94 relaxation (RDKit).
Conformer generation is computationally expensive ($\sim$0.5~s per molecule for
flexible drug-like compounds).
To avoid redundant computation across training epochs and evaluation splits,
conformers are pre-generated once and stored as
\texttt{.pkl} archives keyed by canonical SMILES.
During training, the data loader reads cached conformers; cache misses fall back
to on-the-fly generation. A small fraction of conformers ($<2\%$) fail to generate
for flexible or metal-coordinated molecules across all seven datasets; these are
handled with fallback flags to prevent training interruption.

%% -----------------------------------------------------------------------------
\phantomsection\addcontentsline{toc}{subsection}{Section S3: PEARL Custom Trainer - Loss Functions, Class Weights, and Evaluation}
\subsection*{Section S3: PEARL Custom Trainer - Loss Functions, Class Weights,
and Evaluation}
%% -----------------------------------------------------------------------------

\paragraph{Loss functions.}
PEARL implements three loss functions selectable per run:

\begin{itemize}[leftmargin=2em]
\item \textbf{Focal Loss (FL).}
  $\mathcal{L}_\text{FL}(p_t) = -\alpha_t (1 - p_t)^\gamma \log p_t$
  with $\gamma = 2$ and $\alpha_t$ set by class frequency.
  The $(1 - p_t)^\gamma$ modulating factor down-weights easy examples and focuses
  training on hard, misclassified samples. FL is particularly effective for tasks
  with challenging examples (e.g., DILI, BACE).

\item \textbf{Weighted Cross-Entropy (WL).}
  $\mathcal{L}_\text{WL} = -\sum_c w_c \log p_c$
  with class weight $w_c = N / (C \cdot n_c)$, where $N$ is total training samples,
  $C$ is the number of classes, and $n_c$ is the count for class $c$.
  Weighting the loss by inverse class frequency is preferred for severe imbalance
  (BBBP, Flavor, hERG) where FL's hard-example focus is less critical
  than correcting the class prior.

\item \textbf{Huber Loss (regression).}
  $\mathcal{L}_\text{Huber}(y,\hat y) = \tfrac{1}{2}(y-\hat y)^2$ if $|y-\hat y|\le\delta$,
  else $\delta(|y-\hat y|-\tfrac12\delta)$, with $\delta=1.0$. Used for both Caco-2
  and Half-Life; Half-Life's target is additionally log1p-transformed before loss
  computation and inverse-transformed before evaluation, since half-life values
  span nearly three orders of magnitude and are heavily right-skewed even after
  IQR-based outlier removal.
\end{itemize}

\paragraph{Class weight computation.}
For binary tasks, scale\_pos\_weight = $n_\text{neg} / n_\text{pos}$ is passed to
tree-based models (XGBoost, LightGBM, CatBoost) during ML-stage training,
matching the class imbalance correction applied during CLM finetuning. Regression
targets (Caco-2, Half-Life) are trained without sample weighting.

\paragraph{Evaluation metrics.}
Classification results report:
\begin{itemize}[leftmargin=2em]
  \item \textbf{MCC} (Matthews Correlation Coefficient): primary ranking metric,
    robust to class imbalance.
  \item \textbf{AUC}: area under the ROC curve; macro one-vs-rest for multi-class.
  \item \textbf{F1$_\text{mac}$} / \textbf{F1$_\text{mic}$}: macro-/micro-averaged F1.
  \item \textbf{Accuracy, Precision$_\text{mac}$, Recall$_\text{mac}$}:
    macro-averaged precision and recall.
\end{itemize}
Regression results (Caco-2, Half-Life) report R\textsuperscript{2}, MAE, and Spearman
rank correlation; \textbf{Spearman is the primary ranking metric}, not R\textsuperscript{2},
since R\textsuperscript{2} is unstable on these small ($n<200$) test sets.
All metrics are computed on a held-out test set unseen during training and
hyperparameter optimization.
Optuna (20 trials, TPE sampler) is used for ML-stage hyperparameter search
(maximizing validation MCC for classification, minimizing validation RMSE for
regression via 5-fold CV).

\paragraph{Bootstrapped confidence intervals and the $\pm1$~SE overlap convention.}
Every metric reported anywhere in this paper or supplement has an accompanying
bootstrapped SE (10,000 resamples of the fixed test-set predictions, stratified by
class label for classification, unstratified for regression; normal-approximation).
This revision introduces a second, stricter overlap convention alongside the
original $\pm1.96$~SE (95\%~CI) band: a $\pm1$~SE band, used specifically for the
head-to-head "does the CLM ladder beat PC-only" comparisons in the main text
Discussion and Section~S5 below. Both conventions use the identical underlying SE;
only the multiplier on the comparison band changes.

\subsection*{Section S4: RAFE Pipeline Details}

\paragraph{ZINC-250k preparation.}
ZINC-250k~\cite{gomez2018automatic} contains 249{,}455 drug-like molecules.
The raw dataset is cleaned by: (i)~removing molecules that cannot be parsed by
RDKit; (ii)~standardising SMILES with RDKit MolStandardise; (iii)~computing
LogP, QED, and SAS (Synthetic Accessibility Score) for each molecule.
The cleaned library is re-embedded independently for each of the seven PEARL
datasets, using that dataset's own task-specific finetuned model (ChemBERTa,
MolFormer, or Uni-Mol with LoRA weights), and normalized to unit $\ell_2$ norm.
For the four TDC ADMET datasets, ZINC-250k re-embedding, FAISS index
construction, and RAFE feature extraction all route their (large) intermediate
artifacts through a dedicated extras volume, separate from the git-tracked
repository, mirroring the storage convention already used for the original four
datasets.

\paragraph{FAISS index construction.}
For each (dataset, CLM variant, loss) combination, a separate FAISS
\texttt{IndexFlatIP} (exact inner-product, equivalent to cosine similarity for
$\ell_2$-normalised vectors) is built over the ZINC-250k embeddings on GPU
(\texttt{GpuIndexFlatIP}) and serialized to a CPU-compatible index file for
portable retrieval. hERG and DILI build 6 SMILES-based + 2 Uni-Mol indices each
(matching the FL/WL loss split); Caco-2 and Half-Life build 3 SMILES-based + 1
Uni-Mol index each (Huber loss only, no FL/WL split for regression).

\paragraph{PCA fitting strategy.}
The centroid component of the RAFE vector is PCA-compressed to 32 dimensions,
fit on the \emph{training} split only and applied without re-fitting to the
validation and test splits, preventing any data leakage from retrieval -- unchanged
from Revision 1 and applied identically to all seven datasets.

\subsection*{Scope and Methodology}

This section has two parts. First (unchanged in spirit from Revision 1), Table~S10
compares PEARL against published external methods on BACE, BBBP, and Flavor -- the
three MoleculeNet-era datasets for which comparable external LoRA/GNN literature
numbers exist. Second, Table~S11 reports the
in-house PC-only, Chemprop, and GCN baselines run on all seven datasets, under
the identical scaffold split, preprocessing, and bootstrapped-CI protocol as every
CLM-based method in this paper -- directly addressing the concern that GNN
baselines in Revision 1 were only ever cited from external papers, never run
under the same protocol as PEARL's own pipeline.

\subsection*{Method Descriptions}

\noindent\textbf{Chemprop / D-MPNN}~\cite{yang2019chemprop}.
Directed Message Passing Neural Network with a learned bond-message-passing scheme.
In this revision, re-implemented and re-trained in-house (Optuna hyperparameter
search over depth/hidden\_size/ffn\_num\_layers/dropout, 20 trials, plus a final
longer run) on all seven datasets, reading predictions back from Chemprop's own
\texttt{test\_preds.csv} and scoring with the identical sklearn metric functions
used throughout this paper.

\noindent\textbf{GCN (this work, in-house)}.
A hand-rolled Graph Isomorphism Network (\texttt{GINConv} $\times N$ layers +
BatchNorm + global mean pool + MLP head). Atom features: one-hot(atomic number,
up to 100) + one-hot(degree) + one-hot(hybridization) + one-hot(H count) +
aromatic/in-ring/formal-charge flags (124-dim); bonds unfeaturized (binary edges).
Optuna search (20 trials) over num\_layers/hidden\_dim/dropout/lr, early-stopped
on validation loss.

\noindent\textbf{PC-only (this work, in-house)}.
A tree ensemble (XGBoost/LightGBM/CatBoost, Optuna-tuned identically to the
CLM-based FT Embed(+PC)/RAFE stages) trained directly on the 473-dim PC feature
vector, with \emph{no} CLM component. Included on all seven datasets as the floor
against which every CLM-based method is judged.

\noindent\textbf{GROVER}~\cite{rong2020grover}, \textbf{AttentiveFP}~\cite{xiong2020attentivefp},
\textbf{Mole-BERT}~\cite{xia2023molecbert}, \textbf{Uni-Mol (full FT)}~\cite{zhou2023unimol},
\textbf{MolFormer (full FT)}~\cite{ross2022molformer}, \textbf{FART}~\cite{zimmermann2024fart}.
External literature baselines, unchanged from Revision 1; see original descriptions.
No comparable external LoRA/GNN literature baseline exists for hERG, DILI, Caco-2,
or Half-Life.

\subsection*{Key Observations}

\paragraph{BACE:} the only dataset in this study where a CLM-based method (Uni-Mol E2E LoRA) clears PC-only at both SE conventions -- consistent with BACE being the most geometry-critical task (3D ligand-receptor binding). PEARL Uni-Mol WL (AUC~$=0.891$) is also competitive with GROVER-Large ($0.894\pm0.028$).

\paragraph{BBBP:} RAFE's point-estimate lead over PC-only ($+0.039$ MCC) is the second-largest margin in this study and the closest to clearing $\pm1$~SE without doing so.

\paragraph{Flavor:} PC-only, Chemprop, and RAFE are within 0.005 MCC of each other; the CLM ladder provides no meaningful lift here.

\paragraph{hERG and DILI:} both TDC ADMET classification tasks show the same pattern as Flavor -- a real but statistically unconfirmed point-estimate lead for the best CLM-based method.

\paragraph{Caco-2:} PC-only outright wins; this is the clearest example of a physicochemical feature set being mechanistically better-matched to the task (membrane permeability) than any learned CLM representation.

\paragraph{Half-Life:} the noisiest dataset studied; FT Embed's point-estimate lead ($+0.098$ Spearman over PC-only) is the largest relative margin among the regression tasks but does not survive $\pm1$~SE given the small ($n=133$) test set.
